## 一、什么是 Agent（智能体）

### 1.1 核心公式

```
Agent = LLM + Memory + Tool + RAG + MCP + Skills
```

Agent 不是直接调用大模型接口，而是围绕大模型（LLM）的不足，给它扩展各种能力模块，使其成为一个能**自主思考、规划、执行任务**的智能体。

### 1.2 纯 LLM 的局限性及解决方案

| 问题 | 解决方案 |
|------|----------|
| LLM 是无状态的（Stateless），无法记住历史对话 | **Memory 模块**（数据库/前端存储/Redis） |
| LLM 只能给思路，不能实际操作网页 | **Tool Use 模块**（工具调用能力） |
| LLM 不知道企业内部私有文档 | **RAG 模块**（检索增强生成） |
| LLM 预训练数据不是最新的（如最新新闻） | **MCP / 第三方 Tool**（如搜索工具） |
| LLM 不能做 PPT、自动炒股等复杂任务 | **Skills 技能**（蒸馏/编排） |

### 1.3 Agent 工作流程

```
User（Prompt 提出复杂任务）
  → Agent 智能体接收
    → LLM Planning / Reasoning（规划与推理）
      → 是否需要 Memory？（记忆模块）
      → 是否需要调用 Tool？（分步骤、多工具）
      → 是否需要 RAG？（查询知识库 → Prompt Template）
    → Response → User（任务完成）
```

### 1.4 知名 Agent 产品

- **Claude Code / Codex**：Coding Agent（编程智能体）
- **小龙虾 / Manus**：自动化任务 Agent

## 二、Agent 开发框架：LangChain

### 2.1 技术栈

```
Node.js (NestJS) + LangChain（单智能体） + LangGraph（多智能体）
```

结合后端技术，开发 AI 全栈 Agent 产品，通过 **Harness Engineering** 落地，实现 AI 技术的商业价值（FDE）。

### 2.2 LangChain 核心能力

#### （1）LLM 层 — 统一兼容各大模型

```js
// 来自 index.mjs — 通过 @langchain/openai 统一接口调用不同模型
import { ChatOpenAI } from '@langchain/openai';
import 'dotenv/config';

const model = new ChatOpenAI({
    modelName: process.env.DEEPSEEK_MODEL,    // 支持 DeepSeek 等
    apiKey: process.env.DEEPSEEK_API_KEY,
    configuration: {
        baseURL: process.env.DEEPSEEK_BASE_URL,  // 兼容任意 OpenAI 兼容接口
    }
});

const response = await model.invoke('棍王杯台球比赛应该设置什么奖励?');
```

**要点**：
- `@langchain/openai` 不仅支持 OpenAI，还兼容所有 OpenAI 接口格式的大模型（如 DeepSeek）
- `dotenv` 管理 API Key 等敏感配置
- `model.invoke()` 是 LangChain 统一调用入口

#### （2）Tool 层 — 让 LLM 能执行操作

Tool 由两部分组成（来自 `tool.mjs`）：

**① 异步处理函数**（实际执行的逻辑）
```js
const readFileTool = tool(
    async ({ filePath }) => {
        const content = await fs.readFile(filePath, 'utf-8');
        console.log(`[工具调用] read_file(${filePath}) 成功读取 ${content.length} 字节`);
        return content;
    },
    // ...
);
```

**② 函数描述对象**（给 LLM 看的"说明书"）
```js
{
    name: 'read_file',                    // 工具名称
    description: `用此工具来读取文件内容...`, // 详细功能描述，覆盖场景、参数需求
    schema: z.object({                     // 参数约束（Zod 验证）
        filePath: z.string().describe('要读取的文件路径')
    })
}
```

**Tool 调用流程**：

1. LLM 判断需要调用工具 → 停止生成，返回 `tool_calls`
2. `tool_calls` 包含：`id`、`name`、`arguments`
3. 执行对应工具函数，用 `id` 关联结果
4. 将工具结果返回 LLM，继续生成最终回复

```js
// 注册工具到模型
const modelWithTools = model.bindTools(tools);

// 构建消息（System + Human）
const messages = [
    new SystemMessage(`你是一个代码助手...`),
    new HumanMessage('请读取 tool.mjs 文件内容并解释代码'),
];

// 调用
let response = await modelWithTools.invoke(messages);
messages.push(response);
```

**消息类型**（`@langchain/core/messages`）：

| 类型 | 角色 | 用途 |
|------|------|------|
| `HumanMessage` | user | 用户输入 |
| `SystemMessage` | system | 系统提示词（设定 Agent 行为） |
| `AIMessage` | assistant | LLM 的回复 |
| `ToolMessage` | tool | 工具执行结果 |

## 三、性能优化：Promise 异步并行

### 3.1 为什么需要并行

Agent 任务复杂时可能调用多个 Tool，或同一 Tool 调用多次。如果串行执行（一个等一个），总耗时会叠加。

### 3.2 核心知识点（来自 `1.html`）

#### Promise 三种状态

```
Pending（等待中）
  → Fulfilled（已成功）
  → Rejected（已拒绝）

状态只能从 Pending 变为 Fulfilled 或 Rejected，且不可逆转。
```

#### async/await vs Promise.all

**❌ 串行（慢）**：
```js
const weatherData = await getWeather();  // 等待 2000ms
const tweetsData = await getTweets();    // 再等 500ms
// 总耗时 ≈ 2500ms
```

**✅ 并行（快）**：
```js
const [weatherData, tweetsData] = await Promise.all([
    getWeather(),   // ┐
    getTweets()     // ┤ 同时执行，等待最慢的那个完成
]);                 // ┘
// 总耗时 ≈ 2000ms（取最大值）
```

#### 关键结论

- `Promise.all([p1, p2, p3])`：并行执行多个 Promise，**等待所有完成**才返回结果
- 结果顺序与 Promise 数组顺序一致
- 适用于**互不依赖**的独立任务（如同时读多个文件、同时调用多个 API）
- `await` 是 ES8 语法：将异步代码写成同步风格，更易读
- `Promise` 是 ES6 提供的异步语法

简易 Agent = LLM + Tool（文件系统 + 命令行）

## 五、关键概念速查表

| 术语 | 含义 |
|------|------|
| **LLM** | 大语言模型（Large Language Model），如 GPT、DeepSeek |
| **Agent** | 智能体 = LLM + 扩展能力模块 |
| **Memory** | 记忆模块，解决 LLM 无状态问题 |
| **Tool Use** | 工具调用，让 LLM 能执行实际操作（读文件、发请求等） |
| **RAG** | 检索增强生成，查询私有知识库增强回答 |
| **MCP** | Model Context Protocol，第三方工具协议 |
| **Skills** | 技能编排/蒸馏，完成复杂多步骤任务 |
| **LangChain** | JS/Python AI 开发框架，统一 LLM 接口 + 工具管理 |
| **LangGraph** | LangChain 生态中的多智能体编排框架 |
| **Zod** | TypeScript Schema 验证库，定义 Tool 参数约束 |
| **tool_calls** | LLM 返回的工具调用列表（含 id/name/arguments） |
| **bindTools** | LangChain 中将工具注册到模型的方法 |
| **Promise.all** | 并行执行多个异步任务，等待全部完成 |
| **Planning** | LLM 的任务规划/推理能力 |
