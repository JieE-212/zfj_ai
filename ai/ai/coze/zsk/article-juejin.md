> 大模型人人都会用了，但真正能落地的 AI 应用，拼的不是模型大小，而是"知识"的精准度。本文带你从零搭建一个带知识库的课程客服智能体，全程无需一行代码。

## 一、AI Agent 究竟是什么？

2025年被称为"AI Agent元年"。但很多人在问：**AI Agent 和大模型聊天机器人到底有什么区别？**

简单来说，一个完整的 AI Agent（智能体）包含两个核心部件：

- **大脑（大模型）**：负责理解、推理、决策 —— 这是"智能"的来源
- **手脚（工具链）**：负责执行具体任务 —— 这是"体"的部分，让智能能动起来

> 🖼️ **[图1] AI Agent 架构示意图** → 见 `article-images/01-agent-architecture.png`

打个比方：大模型就像一个博学但被困在图书馆里的教授，他什么都知道，但无法走出图书馆去查最新资料、也无法调取你公司内部的文档。而 AI Agent 则是给这位教授配上了手机、电脑和公司内网权限 —— 他能查、能找、能动。

**真正的落地价值就在这个"动手能力"上。**

## 二、知识库：AI Agent 的"外脑"

### 2.1 大模型的先天短板

通用大模型有两个致命瓶颈：

| 短板 | 说明 |
|------|------|
| **知识过时** | 训练数据有截止日期，最新的行业动态、政策法规一概不知 |
| **知识私有化缺失** | 你公司的产品手册、内部SOP、客户FAQ，大模型完全没见过 |

这两个问题正是企业级 AI 落地最大的"拦路虎"。**你不可能把公司内部的每一份文档都塞进模型的训练数据里** —— 成本高、周期长、且每次更新都要重新训练。

**解决方案是什么？知识库（Knowledge Base）。**

### 2.2 知识库的本质

知识库不是简单地把文件"喂"给 AI，而是一套完整的**知识工程流水线**：

- 📥 **清洗**：去除噪音数据，统一格式
- 🔍 **鉴别**：筛选高质量、可信赖的知识源
- 🗂️ **整理**：分段、向量化、建立索引
- 💾 **存储**：接入向量数据库，支持高效检索（RAG）

> 🖼️ **[图2] RAG知识库检索增强生成流程** → 见 `article-images/02-rag-flow.png`

当用户提问时，Agent 先从知识库中检索相关内容，再结合大模型的推理能力生成回答 —— 这便是**检索增强生成（RAG）**的核心思路。

## 四、实战：搭建课程客服智能体

下面我们一步步搭建一个真实的课程客服 Agent，它会基于课程资料知识库来回答学员问题。

### Step 1：新建 Agent

登录 Coze 控制台 → 点击「创建 Bot」→ 填写基本信息。

### Step 2：编写 Prompt（最关键的一步）

Prompt 是 Agent 的"灵魂"，它决定了 Agent 的性格和能力边界。核心规则只有两条：

**① 给它一个人设**

```
你是一个专业、耐心、友好的编程课程客服机器人。
你的名字叫"小课助手"。
```

**② 划清边界 —— 能干什么、不能干什么**

```
【你能做】
- 回答课程内容相关问题（大纲、知识点、作业要求）
- 提供学习路径建议
- 解答常见技术疑问

【你不能做】
- 不回答与课程无关的问题
- 不代替老师批改作业或打分
- 不提供课程退费、价格等教务信息（请转人工）
- 不确定的事情要说"我不确定"，不要编造
```

> 🖼️ **[图4] Prompt 人设设计对比（好 vs 坏）** → 见 `article-images/04-prompt-design.png`

**这两条看似简单，但恰恰是新手最容易踩的坑。** 一个没有边界的 Agent 会变成一个"什么都敢说"的嘴炮 —— 这在企业场景里是灾难性的。

### Step 3：配置知识库

Coze 支持多种知识库类型：

| 类型 | 适用场景 | 格式 |
|------|---------|------|
| 📄 文本 | 产品手册、FAQ、制度文件 | TXT / Word / PDF |
| 📊 表格 | 价格表、规格参数表 | Excel / CSV |
| 🌐 在线数据 | 官网文档、帮助中心 | URL 抓取 |
| 🗄️ 数据库 | 结构化业务数据 | MySQL / PostgreSQL |
| 🏢 企业系统 | 飞书文档、内部Wiki | 飞书等集成 |

> 🖼️ **[图5] 知识库类型全景图** → 见 `article-images/05-knowledge-types.png`

对于课程客服场景，我们主要使用**文本文档上传**：把课程大纲、章节摘要、常见问题 FAQ 整理成 PDF 或 Markdown，一键上传即可。Coze 会自动完成分段、向量化和索引构建。

### Step 4：测试 & 发布

配置完成后，在右侧预览窗口测试几个典型问题：

- "这门课包含哪些章节？" → Agent 检索课程大纲知识库回答
- "第三周的作业是什么？" → Agent 检索对应章节内容回答
- "今天天气怎么样？" → Agent 礼貌拒绝（边界生效）

确认无误后，发布到 Web、飞书、微信客服等渠道。

## 五、总结与思考

回到问题的本质：**为什么企业需要知识库 Agent，而不是直接使用通用大模型？**

答案是**精准度 + 可控性**。

通用 LLM 像一个"什么都知道一点"的实习生，而知识库 Agent 是拿着你公司内部手册的**老员工**。他知道什么该说、什么不该说，说出来的每句话都有据可查。

> 通用的泛泛的 LLM，永远不如有知识库的 AI Agent。

对于大多数企业来说，**真正的 AI 落地不是训练一个大模型，而是用好一个大模型 + 你的私有知识。** Coze 这类平台的意义就在于：它把这件事的成本从"需要一个算法团队"降到了"一个人花一下午"。
