# 从零搭建WeUI风格页面：BEM命名规范与HTML5语义化实战

> 本文是一篇面向初中级前端开发者的技术分享，以一个WeUI风格的按钮页面为切入点，深入讲解HTML5语义化标签、BEM命名规范、CSS Reset等前端基础但至关重要的知识点。代码虽小，规范不小。

## 前言

在前端开发的世界里，写一个页面并不难。但写出一个**结构清晰、可维护、符合国际规范**的页面，却是一门需要持续打磨的手艺。最近在整理WeUI页面开发的学习笔记时，我深刻体会到：**优秀的页面开发不是从样式开始的，而是从搭建一个合理的结构开始的。**

本文将以一个WeUI风格的按钮页面为例，从结构到样式、从规范到细节，分享那些看似基础却决定前端工程师段位的关键知识点。

![BEM页面结构总览](./img_page_overview.svg)

## 一、先写结构，再写样式 —— 最高效的开发套路

很多前端新手（包括曾经的我）的习惯是：打开编辑器就开始写样式，边写边调，结果页面越写越乱，class命名越来越随意，最后连自己都看不懂。正确且高效的套路是——**先搭建HTML骨架，确保层次清晰，再逐步添加样式**。

```html
<div class="page">
  <header class="page__hd">
    <h1 class="page__title">这是一个页面</h1>
    <p class="page__desc">这是一个页面的描述</p>
  </header>
  <main class="page__bd">
    <div class="button-sp-area">
      <a href="#" class="weui-btn weui-btn_primary">主要按钮</a>
      <a href="#" class="weui-btn weui-btn_default">次要按钮</a>
    </div>
  </main>
</div>
```

**结构先行，意味着你在动笔之前就已经想清楚了页面的层次关系。** 这就像盖房子先画图纸，而不是一边砌墙一边改设计。这也是团队协作中最重要的习惯——代码首先是写给人看的，其次才是给机器执行的。

![页面结构分层示意](./img_page_layout.svg)

## 二、HTML5语义化标签 —— 让标签"会说话"

在上面的结构中，我们没有使用 `div` 套 `div` 的无脑嵌套，而是用了 `<header>`、`<main>`、`<h1>` 等语义化标签。这是HTML5赋予我们的核心能力——**让标签本身就有意义**。

- `<header>` 代表页面的头部区域
- `<main>` 代表页面的主体内容区
- `<h1>` 是页面的一级标题

这些标签不仅让代码**对人类更友好**，对**SEO和屏幕阅读器也极为友好**。当你写下一个 `<header>` 时，搜索引擎和辅助设备都能准确理解："这是页面的头部，这里是核心导航区域。"

与之配套的是CSS中对HTML5块级元素的兼容处理：

```css
article, aside, details, figcaption, figure,
footer, header, hgroup, menu, nav, section {
  display: block;
}
```

在旧版IE等浏览器中，这些HTML5新增的语义化标签默认不被识别为块级元素，这行样式确保了跨浏览器的完美兼容。**好的前端工程师会考虑兼容性，而不仅仅是"在我的Chrome上能跑"。**

## 三、BEM命名规范 —— 告别"命名困难症"

CSS最令人头疼的问题之一就是给class起名字。`box1`、`box2`、`wrapper-inner-outer`……这些名字**过一周你自己都看不懂**，更别提团队协作了。

**BEM（Block Element Modifier）是国际上最流行的CSS命名方法论**，它用一种约定俗成的符号体系，优雅地解决了这个难题。

![BEM命名规范图解](./img_bem_structure.svg)

BEM将页面拆解为三个核心层级：

| 层级 | 符号 | 含义 | 示例 |
|------|------|------|------|
| **Block（块）** | 独立单词 | 一个独立的、有意义的组件 | `.page`、`.weui-btn` |
| **Element（元素）** | `__`（双下划线） | Block下的子元素 | `.page__hd`、`.page__bd` |
| **Modifier（修饰符）** | `_`（单下划线） | 不同的状态或变体 | `.weui-btn_primary` |

来看我们的按钮组件：

```css
.weui-btn { }             /* Block：按钮组件 */
.weui-btn_primary { }     /* Modifier：主要按钮，绿色背景 */
.weui-btn_default { }     /* Modifier：次要按钮，灰色背景 */
```

三个class清晰地表达了：这是**weui框架中的按钮组件**，有不同的**视觉状态**（主要/次要/禁用/加载中）。如果没有BEM，你可能需要想三个完全不同的名字，而现在只需要在同一语义体系下做逻辑扩展。

### BEM的四大核心优势

1. **国际规范，全球通用** —— 你写的代码，世界各地的开发者都能秒懂
2. **结构清晰，层次分明** —— Block和Element的关系一目了然，搭建盒模型方向明确
3. **简单易读，降低心智负担** —— 用最简单的英文单词表达结构关系，不需要绞尽脑汁
4. **彻底解决命名难** —— 不再为同一组件的不同部分想三个毫无关联的单词

```css
/* 没有BEM时：需要三个独立命名的class */
.page { }
.header { }    /* 哪个页面的header？不知道 */
.title { }     /* 哪里的title？语义丢失了 */

/* 有了BEM：语义关系一目了然 */
.page { }
.page__hd { }     /* 这是page的头部 */
.page__title { }  /* 这是page的标题 */
```

## 四、CSS Reset —— 先把画布变成一张白纸

不同浏览器对默认样式有着各不相同的处理：Chrome的 `<body>` 自带8px的margin，Firefox的列表有自己的padding差异……如果不做统一处理，同一个页面在不同浏览器上可能"货不对板"。

**CSS Reset的核心目的，就是把所有浏览器的默认样式统一归零，让页面变成一张干净的"白纸"，然后你在这张白纸上自由创作。**

![CSS Reset对比示意](./img_css_reset.svg)

这里有一个重要的**性能注意事项**：我们**不使用通配符 `*`** 来做Reset：

```css
/* ❌ 不推荐：通配符匹配所有元素，性能差 */
* {
  margin: 0;
  padding: 0;
}
```

而是**显式列出所有需要重置的元素标签**，这是更规范、性能更好的做法。在实际项目中，更推荐使用 `normalize.css` 这样经过社区千锤百炼的标准化方案——它不只是粗暴地清零，而是在保留有意义的默认样式的同时，统一各浏览器的差异。

## 五、微信UI细节 —— 像素级的体验追求

WeUI是微信官方设计语言的前端实现。在我们的按钮中，有几个值得所有前端工程师学习的细节：

![按钮像素还原详解](./img_button_detail.svg)

```css
.weui-btn {
  font-size: 17px;              /* UI设计师标注的精确字号 */
  line-height: 1.41176471;      /* 24÷17=1.41176471，保留八位小数 */
  border-radius: 8px;           /* 微信WeUI标准的圆角值 */
  -webkit-tap-highlight-color: rgba(0, 0, 0, 0);  /* 去掉移动端点击高亮 */
  user-select: none;            /* 防止用户误选按钮文字 */
}
```

`line-height: 1.41176471` —— 这个数字不是乱写的。UI设计师标注**按钮高度为24px，字体大小为17px**，行高 = 24 ÷ 17 = 1.41176471，精确到八位小数。**这就是像素级还原的力量：不是你"觉得差不多"，而是精确地还原设计师的每一个像素意图。**

此外，`-webkit-tap-highlight-color` 去掉了移动端点击时的默认高亮色块，`user-select: none` 防止用户误选按钮文字——这些"不起眼"的细节，恰恰体现了**对移动端用户体验的深入理解和极致追求**。

## 六、AI时代的Prompt工程 —— 规范和审美是你的护城河

AI辅助编程的时代已经到来，但你给AI的Prompt质量直接决定了生成代码的质量。在这个项目实践中，我们给AI的提示词包含了三条关键信息：

1. ✅ 使用HTML5语义化标签
2. ✅ 遵循BEM命名规范  
3. ✅ 进行CSS Reset（不使用通配符 `*`）

![AI Prompt工程流程](./img_ai_prompt.svg)

**这就是"好的Prompt"——不是模糊地说"帮我写个页面"，而是把规范和约束明确地表达出来。** AI是你的工具和加速器，但编程规范、设计审美和工程判断力，是你的核心竞争力，也是AI无法替代的护城河。你知道什么是好的代码，你知道BEM比随意命名强在哪里，你知道CSS Reset为什么不能用通配符——这些才是你作为工程师真正的价值所在。
